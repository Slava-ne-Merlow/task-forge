# UX-концепция TaskForge

## Персоны

### Персона 1: Антон, Team Lead (35 лет)

**Роль в продукте:** Lead — создаёт задачи, распределяет по разработчикам, апрувит ревью.

**Цели:**
- Видеть статус всех задач в проекте без звонков и Telegram-вопросов
- Быстро находить узкие места: кто перегружен, что зависло в ревью

**Важно в первые 30 секунд:**
Открыть доску команды → увидеть все 4 колонки с задачами → понять где Review без апрува.

**Ожидания:**
- Апруव одним кликом прямо из карточки задачи
- Фильтрация доски по исполнителю, чтобы видеть загрузку конкретного разработчика

---

### Персона 2: Катя, Developer (26 лет)

**Роль в продукте:** Developer — берёт задачи, работает, логирует время, переводит в ревью.

**Цели:**
- Понимать свои задачи на текущий день и неделю
- Фиксировать реально потраченное время без лишней бюрократии

**Важно в первые 30 секунды:**
Открыть «My Tasks» → увидеть свои задачи отсортированные по дедлайну → взять следующую.

**Ожидания:**
- «Take task» — один клик чтобы назначить себе unassigned задачу
- Лог работы: текстовое поле + часы, не более 2 полей
- Нотификация (визуальная) о просроченном дедлайне

---

## User Stories

### 1. Регистрация через инвайт

> Как **новый участник команды**, хочу **перейти по ссылке-инвайту и сразу зарегистрироваться**,
> чтобы не нужно было просить Owner добавить меня вручную.

Шаги:
1. Получаю ссылку `/auth/invite/:token` от Lead
2. Открываю — вижу кто приглашает и в какую команду
3. Заполняю email, имя, пароль → нажимаю «Join & Create account»
4. Автоматически авторизуюсь и попадаю на страницу команды

Done-критерий: пользователь создан, добавлен в команду с ролью Developer, токен помечен как использованный.

---

### 2. Создание задачи и назначение исполнителя

> Как **Lead**, хочу **создать задачу с дедлайном и назначить её разработчику**,
> чтобы он знал что делать и к какому сроку.

Шаги:
1. Открываю доску проекта → нажимаю «Add task»
2. Ввожу название, выбираю исполнителя и дедлайн
3. Устанавливаю приоритет и оценку в часах
4. Задача появляется в колонке «Todo»

Done-критерий: задача видна в колонке Todo, исполнитель получает её в «My Tasks».

---

### 3. Логирование работы и ревью

> Как **Developer**, хочу **зафиксировать время работы и отправить задачу на ревью**,
> чтобы Lead мог проверить результат.

Шаги:
1. Открываю задачу → нажимаю «Log work»
2. Ввожу часы и комментарий → сохраняю (запись появляется в истории)
3. Нажимаю «Move to Review»
4. Lead видит задачу в колонке Review, апрувит → Done

Done-критерий: logged_hours обновлены, в истории есть запись, статус изменён.

---

### 4. Просмотр загрузки участников команды

> Как **Lead или Owner**, хочу **видеть сколько задач и часов у каждого участника**,
> чтобы перераспределить нагрузку.

Шаги:
1. Открываю Team Settings → вкладка «Workload»
2. Вижу таблицу: участник, задачи по статусам, залогировано/оценено часов
3. Вижу кто перегружен (задач больше нормы или логов больше оценки)

Done-критерий: таблица отображает реальные данные, пересчитывается при изменении задач.

## Дизайн-система (TaigaUI 5)

### Используемые компоненты TaigaUI

| Компонент | Где используется |
|---|---|
| `TuiRoot` | Корневой контейнер, theme provider |
| `TuiButton` / `TuiButtonLoading` | Все кнопки действий |
| `TuiTextfield` + `TuiInput` | Формы логина, регистрации, создания задач |
| `TuiError` | Валидация форм |
| `TuiBadge` | Приоритет и статус на карточках и в хедере |
| `TuiDropdown` + `TuiDataList` | Фильтры, сортировка, role-selector |
| `TuiIcon` | Иконки в навигации, кнопках, activity log |
| `TuiAvatar` (directive) | Инициалы пользователя в хедере |

### Кастомные компоненты

- `TaskCardComponent` — карточка задачи (прогресс-бар, assignee, deadline badge)
- `ShellComponent` — навигация с dropdown меню пользователя
- Kanban-колонки — самописный CSS Grid без drag-and-drop

### Цветовая схема

Тёмная тема из коробки TaigaUI 5 (design tokens).
- Accent (кнопки, ссылки): `var(--tui-background-accent-1)` — жёлтый
- Danger: `var(--tui-status-negative)` — красный для overdue и critical
- Success: `var(--tui-status-positive)` — зелёный для Done

## Приоритеты экранов

**Первый экран (после логина):** Список команд → кнопка перехода в Projects.

**Критические экраны:**
1. Kanban-доска проекта — основная рабочая поверхность
2. My Tasks — личный дашборд
3. Task Detail — история, лог работы, апрув/отклонение

**Вторично:**
- Team Settings (роли, инвайты)
- My Projects (агрегированный список)

**Сознательно убрано:**
- Drag-and-drop карточек (сложность реализации vs. польза)
- Уведомления в реальном времени (требует WebSocket)
- Вложения к задачам (требует файловое хранилище)
